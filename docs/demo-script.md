# SecAgent-X 6–8 分钟演示脚本

## 0:00–0:45　定位问题

打开总览页：说明传统大模型容易把“推理”和“执行”混在一起。SecAgent-X 将模型、风险门禁、白名单工具和证据账本拆开，每个结论都能回溯。

强调当前运行 `MODEL_MODE=mock`：它是完全离线、可重复的比赛演示，界面与报告会显示“演示结果”；切换 `auto/live` 并配置密钥后才是 GLM/DeepSeek 真实调用。

## 0:45–2:20　日志事件响应

1. 创建“日志应急响应”任务，授权范围填写“仅分析上传日志”。
2. 上传 `demo_cases/logs/access_attack.log`，开始执行。
3. 展开决策时间线：格式识别 → 日志解析 → 攻击模式 → 时间线。
4. 在 Evidence Ledger 指出 `access_attack.log:1` 等行级来源和 `WEB-SCAN-002`。
5. 打开报告，强调模型解释来自工具证据，不是凭空生成。

## 2:20–4:05　静态源码审计

1. 上传预先生成的 `demo_cases/source_audit/vulnerable_app.zip`。
2. 授权明确写“不执行源码”。
3. 展示安全解压和四个只读工具：项目识别、源码模式、密钥、配置。
4. 在证据中找到 `PY-CMD-001`、`CFG-DEBUG-001`。
5. 指出真实密钥值已显示为 `***REDACTED***`，项目从未被导入或执行。

## 4:05–5:55　被动 Web 分析与人工审批

1. 创建 Web 场景，目标 `http://web-demo/`，授权仅 GET、不提交表单。
2. 开始执行后任务停在 `waiting_human`。
3. 打开审批窗，逐项核对工具 `http_fetch`、风险 `medium` 和完整目标参数，再批准。
4. 展示响应状态/头部观察和表单 `action=/search method=get inputs=q,page`。
5. 说明工具从不提交表单；任何重定向都先重新经过 URL Guard，回环/私网/元数据地址默认阻断。

## 5:55–7:00　模型协同与安全边界

打开“模型与工具”：

- GLM 负责中文任务理解和报告。
- DeepSeek 负责技术计划和证据复核。
- Mock 仅用于离线演示，并明确标记。
- 没有 GPT，没有任意 Shell；高风险和禁用动作不执行。

最后回到任务详情，用“时间线在左、证据账本在右”的布局总结：自主决策不是无限权限，而是在授权、策略和证据约束下完成闭环。

## 7:00–8:00　可选问答验证

- 展示 `docker compose ps` 和 `/api/health`。
- 展示一次 SSRF 单元测试或 ZIP 路径穿越测试。
- 若评委询问真实模型，展示 `.env.example` 的双模型配置，但不要展示或输入真实密钥。
