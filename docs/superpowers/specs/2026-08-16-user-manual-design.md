# SecAgent-X 中文使用手册设计

**目标：** 为普通使用者和管理员提供一份与当前实现一致的中文手册，说明 SecAgent-X 已实现的能力，并覆盖从部署、配置到执行任务和查看报告的完整流程。

## 文档形式

- 新增单篇手册 `docs/user-manual.md`，按使用顺序组织内容，并在 `README.md` 增加入口。
- 同一文档同时服务管理员和分析员；涉及角色限制的操作会明确标注“仅管理员”。
- 使用当前界面的真实菜单、字段和按钮名称，不使用容易随界面变化而失效的截图。
- 命令以 Windows PowerShell 和 Docker Compose 为主，与仓库当前部署方式保持一致。

## 内容结构

1. 产品定位、已实现能力与适用边界。
2. Agent 架构、模型分工、工具执行、风险审批、证据和报告的数据流。
3. Docker 快速启动、服务检查、停止与数据保留。
4. 首次登录、角色权限、账号创建和密码维护。
5. GLM 与 DeepSeek/OpenCode Go 的配置方式，以及网页 API Key 存储流程。
6. 日志响应、源码审计和 Web 分析三类任务的输入要求、示例和执行步骤。
7. 人工审批、任务状态、暂停、恢复、重试和取消。
8. 执行时间线、工具调用、模型调用、证据账本和报告的解读方法。
9. 安全边界、已知限制、常见故障和运维命令。

## 准确性与安全

- 启动命令、URL、默认演示账号、页面路径和状态名称以当前代码及现有部署文档为准。
- 明确 OpenCode Go 是 DeepSeek 阶段使用的 OpenAI-compatible 模型后端，不是远程执行器。
- 只使用占位符描述密钥；不读取或写入 `.env` 中的真实值，也不展示数据库、JWT、加密主密钥或 Provider API Key。
- 明确 `admin/admin` 仅用于本地演示，首次登录后应修改，生产环境不得使用。
- 明确 Web 分析只允许授权目标，并受主机白名单、SSRF 防护、重定向复检和人工审批约束。

## 验证方式

- 检查 Markdown 内部链接和引用文件是否存在。
- 对照前端页面验证菜单、字段、按钮和任务状态名称。
- 对照 Compose、`.env.example`、README 和部署文档验证命令及配置项。
- 执行仓库 Secret 扫描，确认新增文档没有真实凭据或疑似密钥。
- 检查最终差异，确保只增加手册、设计说明和 README 入口，不修改应用行为。
